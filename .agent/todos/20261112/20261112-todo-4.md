# Phase 3 — Phrase Source Collection and JSON Generation

## Tasks

### 01 — Define extraction and enrichment decisions

Review docs/Game/phrase-data.md and decisions-to-finalize.md. Confirm the extraction strategy for the two specified sources, how source terms and attribution are retained, and how missing context and hint content will be researched or authored before implementing the collector.

### 02 — Create the standalone Node.js collector subproject

Create a JavaScript project using Node.js in a dedicated repository subdirectory outside src/. Define package metadata, supported Node version, dependencies, scripts, configuration, and local execution conventions.

### 03 — Implement source extraction adapters

Implement extraction for the agreed phrase sources. Keep source-specific parsing isolated, preserve attribution, and handle pagination or page variations as applicable to the selected sources.

### 04 — Implement phrase enrichment and three-hint preparation

Produce the context and exactly three usable hints required for every phrase. Define a transparent fallback for missing source context and record provenance for extracted versus authored material.

### 05 — Define and generate the JSON interchange format

Define a versioned, documented JSON structure that the Rust importer can validate. Generate output files with stable fields, source references, phrase text, context, hints, and any preparation metadata required by the importer.

### 06 — Handle duplicates, incomplete data, and extraction failures

Implement duplicate detection and explicit handling of missing or malformed records, source changes, request failures, and partial collection runs. Avoid silently emitting incomplete phrase records.

### 07 — Test and document the Node.js collector

Add tests using saved HTML/JSON fixtures or mocked HTTP responses so normal tests do not depend on live websites. Document setup, configuration, execution, output files, known source limitations, and how to review generated records.
