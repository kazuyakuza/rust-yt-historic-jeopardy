# Phase 17 — Viewer Fallback and Audience Timeout

## Tasks

### 01 — Research and resolve viewer API implementation details

Review docs/Game/stream-lifecycle.md and the current Core YouTube API transport. Verify the supported concurrent-viewer field, request prerequisites, and error classifications before implementation. Do not assume a push listener exists.

### 02 — Implement chat-inactivity-triggered viewer polling

Only after the configured period without chat activity, query the current concurrent viewer count. If positive, wait the configured interval before querying again, provided chat remains inactive.

### 03 — Implement zero-viewer timeout and final recheck

When a query reports zero, start the configured no-audience timeout. Before closing, query viewers again; close only if the final result is still zero and no chat activity has resumed.

### 04 — Implement API error retry policy

Treat request errors or unavailable viewer data as unknown rather than zero. Retry at the configured interval and apply the configured maximum consecutive-error policy when chat remains inactive.

### 05 — Test the complete audience fallback state machine

Use fake time and a mock viewer API to test positive counts, zero counts, final rechecks, errors, retry exhaustion, chat activity cancellation, and recovery. Document the exact state transitions and configuration.
