# Phase 4 — Phrase JSON Importer and Data Validation

## Tasks

### 01 — Resolve importer command and JSON contract prerequisites

Review the Phase 3 collector output contract and docs/Game/phrase-data.md. Confirm the CLI mode, import semantics, handling of existing records, and ownership of derived-field calculation before implementation.

### 02 — Implement the Rust phrase-import command

Add a dedicated executable mode or subcommand consistent with the existing CLI conventions. Keep the collector independent; the Rust application consumes its generated JSON files.

### 03 — Implement JSON parsing and validation

Parse the versioned interchange format and validate required fields, source attribution, context, exactly three hints, and other phrase record invariants. Provide actionable record-level errors.

### 04 — Apply canonical preparation and calculate derived attributes

Apply or verify the canonical phrase normalization and preparation rules and calculate individual difficulty and other derived metadata as specified. Do not duplicate preparation logic unnecessarily across tools.

### 05 — Import validated records into SQLite

Persist valid records using the Phase 2 persistence layer. Define safe duplicate/update behavior and ensure invalid records do not corrupt otherwise valid imports.

### 06 — Test importer behavior and document the workflow

Test valid, invalid, incomplete, duplicate, and mixed batches, plus database failures. Document command usage, JSON contract, import reporting, and recovery from failed imports.
