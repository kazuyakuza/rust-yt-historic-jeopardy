# Phase 18 — Maximum Stream Duration and Final Results

## Tasks

### 01 — Resolve stream-duration and shutdown prerequisites

Review docs/Game/stream-lifecycle.md, scoring-and-leaderboards.md, and technical-integration.md. Define the required warning lead time, admission cutoff, active-game cutoff, final-results duration, and Core shutdown handoff before implementation.

### 02 — Implement maximum stream duration tracking

Track elapsed stream time against the configured maximum and expose remaining time to the lifecycle coordinator.

### 03 — Implement game admission near stream end

Use the duration estimate supplied by the historical/admission component to decide whether another game can begin. Do not start a game that cannot reasonably finish within the remaining stream window.

### 04 — Implement active-game end warning and forced completion

When the current game must be the final game, display the configured warning/countdown, then end it at the deadline regardless of phrase completion. Determine standings from scores at cutoff.

### 05 — Implement final results and stream shutdown handoff

Present final stream standings for the configured duration and then request shutdown through the existing Core lifecycle boundary.

### 06 — Test lifecycle timing and document finalization

Test admission boundaries, warning transitions, forced game end, tied final standings, results display duration, and shutdown request behavior with injected time.
